1 · A coding agent at work

The stock DSH Web UI runs DeepSeek-V4-Flash-0731 on the Token Factory public endpoint against real Django issues from SWE-bench Verified. The agent reads the code, edits it and runs tests. Afterwards the official SWE-bench harness applies its patch and runs hidden tests the agent never saw: the tests that must start passing (fail-to-pass) and the existing tests that must keep passing (pass-to-pass).

~/dsh-kit/scripts/launch_web.sh ~/dsh-live --patch ~/dsh-kit/config/tofa-public-deepseek-v4-flash-0731.patch.yml

        
Starts the stock Web UI on the prepared workspace (see docs/LIVE_DEMO.md). A run took 33–250 s and $0.003–0.018 here. The recorded runs are the fallback if the network is down.

    2 · What one task actually costs
    
      
    The 9 SWE-bench trials from section 1, measured per LLM request from DSH's own session log: provider-reported tokens (uncached, cached, output), time to first token, latency and decode speed. Cost = tokens × the verified public list price ($0.14 / $0.01 cached / $0.28 per 1M tokens).

    3 · Are the small tasks representative?
    
      
    Two more realistic tasks on the public endpoint (2 Nov), with the same DSH setup, medium effort and independent hidden tests. M1 (medium): fix a CSV importer and implement a late-penalty grading policy across four modules. H1 (heavy): add per-user token accounting and budget enforcement to a small university LLM gateway. 3 formal runs each, plus 2 pilot runs reported separately. With n = 3, read these as examples, not statistics.

    5 · Pay per token or pay per GPU-hour?
    
      
    Public endpoint: measured tokens per task × verified prices. Dedicated endpoint: GPU-hours × an assumed price. The number of GPUs is sized from benchmark throughput, so bigger volume means more GPUs, not one GPU that absorbs everything.

    6 · A classroom of agents
    
      
    Every simulated student runs real recorded DSH trajectories: the same sequence of LLM requests, token counts and tool gaps that we measured. The simulation then asks whether each backend keeps up, and at what cost.
